Terms of use

Last updated October 29, 2026

These terms apply to anyone who signs in to an idvault console. By signing in you agree to them. Your organization may have its own policies that also apply.

Authorized use only

  • Use only the account and token you were given. Don't share your token. If you think it has been exposed, tell your administrator so it can be replaced.
  • Use idvault only for the work your role covers: taking and checking backups, restoring directory data, approving restores, or reviewing the audit log.
  • Don't try to get around the role checks, approval requirements or snapshot locks, and don't change files in the data directory by hand.

Everything is logged

Every request you make is written to the audit log with your account name and the time, including requests that are refused. The log is designed so that changes to it can be detected.

Restores and approvals

  • A restore changes the live directory. Preview it first and make sure you understand what it will add, change or remove.
  • When you approve a restore, you are confirming that you have reviewed it and that it should run. Only approve requests you have checked.
  • idvault saves the current state before every restore so it can be undone, but restoring can still lock people out or give them access until the undo is done. Coordinate with your team.

Development mode

A server started with -dev uses fixed, publicly known tokens and is meant for local testing with sample data only. Don't run it on a network or with real directory data.

No warranty

idvault is provided as is, without warranty of any kind. The organization running it is responsible for testing its backups and restores, for protecting the server it runs on, and for keeping additional copies of critical data.

Changes to these terms

These terms may be updated with new versions of idvault. The date at the top shows when they last changed.
